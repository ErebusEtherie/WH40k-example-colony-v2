# Colony Manager — Project Overview

A web app that replaces the manual spreadsheet for tracking **Warhammer 40k
Rogue Trader colonies**: it records colony state, computes derived values
(lore states, Profit Factor), and tracks modifiers, infrastructure, support
upgrades, representatives, resources, events, development plans, members
and change history.

> **Scope:** a **tracking / organization tool, not a game automation
> system.** The GM resolves all dice rolls, events and outcomes at the
> table and records the results through the API. There is no automatic
> dice rolling, event progression, growth/decay or time simulation (see
> `SCOPE_CLARIFICATIONS.md`).

## Multi-user

- System roles: `viewer` · `colony_manager` · `admin`
- Colony membership roles: `viewer` · `editor` · `owner`
- Users may belong to many colonies with different roles per colony.
  Permission checks combine both (`adapters/api/middleware/permissions.py`).

## Stack

- **Backend** (`src/colony_manager/`): Python 3.12+, FastAPI, Pydantic v2,
  SQLAlchemy 2.0, Alembic, **SQLite** (default `colony_manager.sqlite` via
  `DATABASE_PATH`), PyJWT (HttpOnly cookie sessions), bcrypt, slowapi
  (rate limiting), Typer CLI, PyYAML rule tables.
- **Frontend** (`src/`): React 19 + Vite, TypeScript (strict), TanStack
  Query v5, Tailwind v4 + Mechanicum `--mech-*` CSS variables, lucide-react,
  motion, `openapi-typescript`-generated API types, Express 5 mock/dev server.
- **Testing:** pytest + Hypothesis (backend); Vitest + React Testing Library +
  MSW + Playwright (frontend); Ruff + Mypy.

## Architecture

Clean architecture / ports & adapters:

```text
adapters/  →  application/  →  domain/
```

`domain/` is pure business logic with zero I/O; `application/` orchestrates
use cases; `adapters/` implement I/O (API, persistence, CLI, config).
Dependencies point inward. Frontends interact only through the REST API
(`/api/v1`) and the SSE stream — never import Python domain code.
